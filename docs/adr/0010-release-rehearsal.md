# ADR 0010 — 06D 发布配置预检与本地恢复

从 06C 的运行时验收转向 HUB-038/040/041 的发布准备。继续保持框架优先，真实鱼糕脚本、真实 DAV、生产资源和部署不在本次执行范围。

预览/生产环境补齐不继承的安全 vars。静态预检拒绝占位或共享 D1、共享 Worker 名、未显式禁用测试路由、危险 Origin、公开秘密值及未经本阶段验收的定时外发。它只输出阻塞代码，不回显秘密值；不能检查云端资源或 Secrets，故相关状态始终为 false。Wrangler dry-run 逐环境单独验证。

恢复演练复用已锁定的 Wrangler、当前迁移与真实 API，不引入 SQLite 替身或新的第三方库。每次使用独立本地配置/状态、只向新空库恢复，无默认数据读写和删除动作。SHA-256 清单绑定 SQL 与当前迁移，再比较整库结构与行摘要（含迁移记账、序列），用 D1 quick_check/外键检查及恢复后的真实 API 证明结果；失败不生成成功报告。原始 SQL 和诊断均被忽略且不作为 CI 附件上传。

整库备份可能包含个人数据、设备摘要和通知订阅，不能复用面向分享的工作台 JSON 导出。SQL 校验不是加密或来源认证；部署 Secrets、浏览器本机密钥和保险箱也不包含在 D1 中。具体入口与维护边界见[维护手册](../operations-runbook.md)。

数据库回退可能使浏览器保存的 Hub 水位领先于服务端，协调器新增水位倒退门禁，拒绝生成新预览且保留检查点。该门禁不能识别所有同水位分叉，生产恢复仍需要 epoch/客户端再接入设计与实际验收；本次不把本地演练等同于生产恢复完成。

复用 TypeScript 现有 JSONC 解析器、Node 标准库哈希/测试/进程 API 和项目现有接口，没有新增依赖，也没有执行云端创建/部署/恢复或修改真实凭证。
