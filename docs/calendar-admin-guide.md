# FF14 Hub 活动管理员：账号密码 + TOTP 双因子

普通玩家继续匿名使用国服活动日历，个人工作空间继续使用设备凭证。**管理员身份另行建立，不使用工作空间的设备令牌授权。**

## 第一次开通

1. 打开「国服活动日历 → 管理员登录」。站点尚无管理员时显示「首次开通管理员」。
2. 设置独立用户名、至少 14 字符的高强度密码，以及部署初始化密钥 `BOOTSTRAP_SECRET`（仅用于首次开通，原密钥需由站点部署者掌握；不要发送到聊天）。
3. 点击创建管理员后，网站**仅在当前页面**显示 TOTP 种子和 `otpauth://` 链接。
4. 在 **Vaultwarden / Bitwarden 的身份验证器**（或任何兼容 TOTP 的工具）里创建项目并填入密钥。参数：SHA-1、6 位数字、30 秒轮换。也可以使用单独的认证器应用。
5. 网站提示绑定时，再输入账号、密码、部署初始化密钥及认证器当前动态验证码，激活账号。
6. 后续直接通过「管理员登录」输入账号、密码和动态验证码，再进入表单维护活动。认证只对本次页面有效；刷新后需要重新登录。

**术语区别：**此实现采用标准 TOTP，不依赖 Vaultwarden 或 HashiCorp Vault 的专用 API。若你指的是 HashiCorp Vault，内置 TOTP Secrets Engine 也能生成标准验证码，但不等同于把 HashiCorp Vault 作为站点身份认证服务。未来如需统一外部身份源，需要单独设计 Vault Auth/OIDC 及其客户端密钥管理。

## 安全与存储边界

- 仅允许一次注册唯一 owner；没有公开管理员注册，创建账号必须持有 Cloudflare 中已配置的 `BOOTSTRAP_SECRET`。
- D1 保存 PBKDF2-SHA256（310000 次）密码摘要及随机盐，绝不保存明文密码。
- TOTP 种子使用 AES-GCM 加密后保存在 D1，加密密钥由 `BOOTSTRAP_SECRET` 派生。**不要随意更换/删除该部署密钥**，否则现有 TOTP 无法解密，必须走管理员恢复或重新绑定流程。
- 动态码每 30 秒变化，容忍一次轻微时钟偏移，但同一时间步的验证码不能再次用于登录。
- 独立管理员登录成功签发随机 Bearer，数据库只存 SHA-256 摘要，默认 8 小时过期；仅保存在前端运行时内存，不写 localStorage、URL、Cookie 或日志。退出登录立即撤销当前会话。
- 登录接口按数据库计数限流；所有管理 CRUD 均在 Worker 服务端验证管理员会话，不依赖按钮是否可见。
- 编辑、隐藏和恢复写入独立的 `calendar_editor_entries`。定时官方同步只更新 `official_calendar_snapshots`，不会覆盖人工编辑。
- `calendar_admin_audit` 记录每次有效变更；乐观锁避免多浏览器并发覆盖。公共 API、ICS 订阅立即获取人工覆盖后的活动。
- 若绑定中途关闭页面而丢失 TOTP 种子，需要由可信运维人员重新配置尚未激活的 owner；**不要在公开页面提供无需初始化密钥的找回通道**。

## 玩家界面

首页活动模块隐藏后，首页仍有「重新显示国服活动」入口；也可从设置勾选重新显示。

活动中心默认只展示未结束活动；已结束的历史日程必须主动选择「历史已结束」。无可靠起止时间的公告留在单独的待确认折叠区，不进入 ICS。首页不再显示重复的「今天」数字，临近截止的窗口调整为 24 小时。

## 管理台

结构化表单可新建、编辑、隐藏、恢复活动。名称、类别、北京时间起止、简介、地点及 HTTPS 来源网址各自单独填写，避免让管理员手写 JSON。两个时间都未核实时请留空，避免产生虚假的倒计时。
