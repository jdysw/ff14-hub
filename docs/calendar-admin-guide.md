# FF14 Hub 活动管理员：账号密码 + TOTP 双因子

> 本指南已根据当前全站 owner 管理员实现更新。首次配置与恢复须通过受控离线运维流程，**没有**网页/API 管理员注册、创建或重新绑定入口。公共与私人数据边界另见 [全站管理员后台操作与安全边界](site-admin-operations.md)。

普通玩家无需工作空间或设备凭证即可浏览公开活动。当前用户导航、备忘与钓鱼标记存储在浏览器 IndexedDB 中；管理员身份与玩家个人资料、历史设备工作空间完全隔离。

## 进入后台与登录

1. 打开 FF14 Hub 的「设置」，在四秒内连续五次点击「设置」标题，进入隐藏的管理员入口。隐藏入口只是降低日常界面干扰，**并非安全防护**。
2. 使用**已存在且已激活**的唯一 owner 管理员账号、密码及 TOTP 动态码登录。TOTP 使用 RFC 6238：SHA-1、6 位数字、30 秒轮换；可由 Bitwarden/Vaultwarden 身份验证器或其他兼容应用生成。
3. 登录后才能访问「站点管理」页面，并从设置直接进入；刷新页面或退出会丢失浏览器内存里的会话凭证。
4. 忘记密码、丢失 TOTP 或尚未完成首次初始化，不能在网页上创建第二个管理员，也不能通过修改部署密钥绕过验证。应在备份和审计前提下走受控离线恢复/初始化流程；当前项目未提供可供用户自行操作的 HTTP 恢复接口。

**不要将 `BOOTSTRAP_SECRET` 提交到仓库、表单截图或聊天记录中。** 它属于部署 Secret，并参与现存 owner 密码摘要和 TOTP 种子的密钥派生，不得随意更换。

## 安全与存储边界

- 唯一 owner 账号存放在 `calendar_admin_accounts`；网页及 `/api/v1/admin` 当前只提供登录、会话验证、退出和有权限的后台操作，没有账号创建端点。
- 服务端对管理员密码使用 **PBKDF2-SHA256 100,000 轮**、随机盐及基于 `BOOTSTRAP_SECRET` 派生的 **HMAC pepper**。D1 不保存明文密码。
- TOTP 种子以 AES-GCM 加密保存，密钥由部署 Secret 派生；每个时间步只接受一次验证码，并容忍相邻时间步的有限偏差。
- 独立管理员 Bearer 会话使用随机高熵令牌，D1 仅存其摘要；默认八小时有效。网页只在运行时内存持有令牌，不写入 localStorage、URL 或 Cookie，退出时撤销。
- 登录接口具备数据库限流；服务端所有管理请求均通过管理员鉴权中间件，任何前端入口隐藏均不能代替授权。
- 国服活动人工编辑、隐藏和恢复记录保存在 `calendar_editor_entries`；官方活动数据快照独立保存，人工编辑不会被定时采集直接覆盖。
- `calendar_admin_audit` 记录有效修改；活动编辑使用修订号避免并发无提示覆盖。
- 当前站点管理权限不等于基础设施权限，不能在网页直接修改 Cloudflare Secrets、D1 绑定、DNS、数据库迁移或部署策略。

## 玩家界面

首页活动模块可以在个人设置中隐藏或重新启用。活动中心区分未结束与历史活动；只有核实过的活动起止时间才可用于准确倒计时或 ICS。

## 管理台

现有管理页面提供全站公开展示设置、导航目录维护和国服活动管理。活动采用结构化表单新建、编辑、隐藏与恢复，可填写名称、时间、简介和来源链接；起止时间尚未核实时不应填写推测值。

详见 [全站管理员后台操作与安全边界](site-admin-operations.md)。
