# 国服活动管理员使用说明

本项目不添加传统账号密码体系。国服官方活动内容公开可读；只有受授权的**设备凭证**能使用活动管理后台。

## 进入后台

1. 在网站右上角「设置 → 会话凭证」保存站点首次初始化时颁发的**设备令牌**（Bearer 设备凭证，不是 Cloudflare API Token）。
2. 返回首页进入「国服活动日历」。
3. 服务端验证设备凭证和管理员权限后，才会显示「管理活动」按钮。点击进入结构化编辑器。
4. 在表单里填写名称、类别、简介、地点、官方来源 URL 和北京时间的开始/结束时间。两个时间都留空则作为待核实公告，不参与月历或 ICS。
5. 保存后即时写入生产 D1，公开日历与 ICS 订阅读取人工修改后的有效内容，不必重新部署。
6. 已隐藏的活动会保留在管理列表中，可以恢复。版本冲突会要求刷新而不是覆盖其他人的编辑。

## 权限分配与撤销

* 首次初始化时，唯一工作空间的首台设备获得管理员角色（existing deployment 通过迁移 0017 将仍有效的初始设备赋权）。
* 普通配对设备即使连接相同工作空间也**不自动拥有管理员权限**。
* 如果初始设备已撤销或令牌遗失，运维人员可以在 Cloudflare D1 控制台中检查设备 ID（不需要也不应查询明文令牌），并明确授权仍然有效的设备。示例 SQL：

```sql
-- 请将下方 :device_id 用 D1 控制台的参数或可信设备 ID 替换；
-- 不要把任何设备令牌写进 SQL 或聊天记录。
INSERT OR IGNORE INTO calendar_admin_devices (device_id, workspace_id, granted_at)
SELECT id, workspace_id, CAST(unixepoch('now') AS INTEGER) * 1000
FROM devices WHERE id = :device_id AND revoked_at IS NULL;
```

撤销后台权限：`DELETE FROM calendar_admin_devices WHERE device_id = :device_id;`。撤销设备凭证后，鉴权中间件也会立即拒绝该设备。

## 数据与审计

* `official_calendar_snapshots` 是官方定时数据源；同步不覆盖人工修改。
* `calendar_editor_entries` 保存创建、覆盖、隐藏、恢复的独立层，支持版本号乐观锁。
* `calendar_admin_audit` 记录每一次已成功写入的操作与操作者设备 ID；不会保存或记录设备令牌。
* 公开接口只返回展示所需活动数据，不包含管理员清单与审计资料。
* 管理员的更改与原始官方活动应保持来源可追溯；不要把未经核实的个人活动描述为官方公告。

## 历史活动与首页隐藏

列表默认「未结束」，历史活动必须显式选择「历史已结束」。没有可靠日期的公告位于折叠区域，不参与倒计时。首页隐藏后，直接点击「重新显示国服活动」，也可以在设置中开启活动模块。
