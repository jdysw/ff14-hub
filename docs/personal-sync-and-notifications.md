# 个人云端同步与每日后台通知

## WebDAV / S3

设置 → 数据管理 → 云端同步。钓鱼导入导出与备份恢复也归在同一数据管理入口。同步覆盖个人网站、收藏、备忘、首页模块顺序/可见性、两个区服的钓鱼进度。采用独立的 `personal.json` 文件，不能填写鱼糕原始文件地址；不接受指向本站、非 HTTPS、内嵌账号或查询参数的地址。

WebDAV 使用 Basic Auth；S3 使用浏览器 WebCrypto 生成 AWS SigV4，支持完整虚拟主机或路径对象地址、Region 和临时 Session Token。凭证用不可导出的 AES-GCM CryptoKey 加密保存在独立 IndexedDB，不上传 Hub，不进入个人备份。远端文件为用户自己的 JSON 备份，包含个人资料，需要私有目录/桶和最小对象读写权限。

浏览器直连要求远端启用 CORS：Origin 为 `https://ff14.zhixia.uk`，方法 GET/PUT/OPTIONS；允许 Authorization、Content-Type、If-Match、If-None-Match，以及 S3 的 x-amz-date、x-amz-content-sha256、x-amz-security-token；Expose-Headers 必须包含 ETag。CSP 仅为此放开 HTTPS connect-src；script-src 和 worker-src 仍为同源。没有服务器 DAV/S3 代理。

先保存配置，再读取远端预览，解决冲突后应用双向同步。同步是用户主动操作；没有后台自动覆盖。保存逐项比较的共同基线，支持删除和取消标记；并发冲突不会凭时间戳静默覆盖。强 ETag + If-Match 或 If-None-Match 条件写防止覆盖远端新版本。用户的服务必须正确实现这些 HTTP 语义；建议启用远端版本历史。网络失败后应重新读取确认是否写入成功。

写入前保留加密的本机快照，可从同一界面恢复。写入远端和更新本机无法组成跨服务事务：本机在预览后变化会停止本机替换，远端结果保留，重新预览即可继续。更换连接目标会清除基线。新设备需要重新填写凭证，首次存在同项不同数据时明确选择保留哪份。

## 通知

设置 → 通知，选择 Server 酱 Turbo（SCT SendKey）或邮件（Resend API Key、已验证域名发件邮箱、收件邮箱）。Server 酱³ 不在当前 Turbo 接口范围。凭证只通过 HTTPS 提交一次；服务端使用部署已有高熵密钥派生独立 AES-GCM key，并以订阅 ID 绑定密文。不能通过状态 API 读回渠道秘密。用于管理当前订阅的随机 token 仅在本机独立加密保存，不进入云端备份。停用时删除凭证及级联任务；90 天不访问自动过期。

后台与前台规则分开：

- 后台鱼窗：每天用户指定的北京时间发送一份今天和明天的日程。跟随本机最后登记的未钓获闹钟鱼，最多 50 条；按开始时间排序，重复窗口逐条保留，跨日区间分组到对应日期。不把缺少验证/含额外条件的规则伪装为已确认窗口。网站关闭后服务器仍每天计算，无需客户端预先登记未来每个窗口。
- 后台活动：可选结束前 3 天、1 天。在每日生成时根据剩余时间向上取整为天数，匹配所选阶段，合并入同一份日程。日程唯一键按订阅和北京时间日期去重，同一阶段不会每天重复；没有可靠结束时间的公告不提醒。使用人工编辑后的官方快照，仍遵守全站 6 小时同步上限。
- 待办：后台登记未来一年内最近 30 个已设提醒的待办；修改、取消和完成状态通过当前订阅更新。长期待办需要在到期前访问网站续期，90 天不访问的订阅会过期。
- 网页内：用户单独授权浏览器 Notification，按本机 30 秒检查和设定提前量提示，秒级倒计时不变。它不向后台登记逐鱼窗口任务。前台与后台可独立使用；后台每日汇总是独立渠道，不以不可靠的“所有网页已经关闭”检测作为发送前提。

仅生产环境注册 `*/5 * * * *`，每天 288 次轻量检查，时间精度约 5 分钟；测试/预览不会继承生产 Cron。新分支不执行旧工作空间的逐鱼规划或空闲心跳写入。每次先用索引查到期订阅及任务，空闲时不读取鱼类目录、不抓官方公告、不访问通知服务；清理每日最多一次。

到期后才读取所需区服的内置静态鱼类目录并生成汇总。一次有界处理最多 5 个订阅，同订阅到期消息合并；数据库租约避免并发抢送，发送完成标记持久化，临时错误最多 3 次尝试，按 UTC 日计的每日上限包含失败尝试。测试消息另限每 5 分钟 2 次。登记受 IP 摘要/全局限流和总订阅上限约束。邮件使用稳定批次幂等键；Server 酱网络中断后无法保证绝对不重复，以渠道记录为准。HTTP 接受不能证明设备/邮箱已收件，用户主动点击测试后在接收端确认。

渠道请求仅使用固定的 sctapi.ftqq.com、api.resend.com；保留原有精确域名 Web Push 实现但不会自动开通 VAPID。拒绝重定向，限制超时和响应体，应用日志不记录地址、密钥、收件人或通知正文。服务器渠道密文与管理员密码共用部署密钥的不同派生用途，不能任意更换 BOOTSTRAP_SECRET。

## 验证与边界

协议单测覆盖条件写冲突、ETag 缺失、地址限制、SigV4 请求、三方编辑/删除/取消钓获；真实 D1 测试覆盖密文与订阅隔离、批量与并发去重、发送上限、有限重试、用户时间、跨日重复鱼窗以及活动 3/1 天选项。所有迁移可重放。

ego lite 真实浏览器验证了本机 AES-GCM 往返和 CryptoKey 不可导出、桌面/手机设置表单与无横向溢出。真实用户 WebDAV/S3、Server 酱和邮件仍需用户配置凭证和远端 CORS 后自行测试，不能用模拟通道结果声称已实际收件。

参考：[S3 条件写](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)、[Server 酱文档](https://sct.ftqq.com/docs/)、[Resend 发送接口](https://resend.com/docs/api-reference/emails/send-email)。
