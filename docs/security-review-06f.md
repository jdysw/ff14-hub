# 06F 框架安全复核

复核日期：2026-10-19（Asia/Shanghai）。范围是当前仓库的发布前框架，不是独立渗透测试或生产安全认证。06E 已合并；真实部署、鱼糕/DAV 接入仍未开启。

## 本轮发现与修复

| 边界 | 发现 | 修复与证据 |
| --- | --- | --- |
| 服务端异常隐私 | 模式脱敏无法识别所有普通短语；错误 name/message、logDetail 和原始路径仍可能含个人正文 | 500/503 返回代码对应的固定文案；501 保留既有预先定义的功能拒绝说明。5xx 不含 details，日志保留 requestId、固定分类/状态，不输出原异常或任意路径。覆盖普通短语异常、ApiError 诊断、数据库探活及认证路径测试 |
| 手工外发入口 | reconcile 没有工作空间级调用预算，轮换设备可继续规划/处理 | 复用现有 D1 原子限流：每空间每分钟 5 次。并发两设备总共只放行 5 次；其他空间不受影响，过期窗口可恢复 |
| 推送注册写入 | 仅有订阅容量，没有请求频率预算 | 每设备 10 次/10分钟、每空间 20 次/10分钟；任一拒绝即返回 no-store 429 与 Retry-After。前一配额已消费不会回滚，是保守的成本控制 |
| 用户取消能力 | 限流可能阻断安全操作 | DELETE 退订不受注册限额影响；注册额度耗尽后仍可立即停用当前设备订阅 |
| 私有浏览器传输 | 部分主站请求沿用 Fetch 默认重定向策略 | 核心 API 客户端和活动/钓鱼/提醒/同步端口统一 redirect:error、omit cookies、no-store；调用方不能覆盖核心客户端策略。凭证继续只在 Authorization 头中，不通过组件数据端口暴露 |

限流发生在认证、模块门禁和结构校验之后；无效输入/匿名请求不消耗工作空间的手工触发额度。内部调度函数不走这个 HTTP 预算，继续使用逻辑去重、租约与发送前复检；本轮没有创建真实 Cron 或发送真实推送。

## 继续有效的边界

- 身份与跨空间访问：设备认证、单例初始化、一次性配对、撤销、幂等与 CAS 仍由真实 D1/HTTP 测试覆盖。
- 导航/导入：HTTPS URL 白名单、严格结构与体积限制，外来内容作为数据处理；本轮未放宽 CSP、脚本来源或 Widget 权限。
- 服务端出站：Web Push 限制为现有三个精确浏览器推送域，手动处理重定向且不跟随；没有服务端 WebDAV 地址或凭证接收入口。
- 客户端同步：独立 HTTPS DAV、条件写、检查点、操作回执及冲突停止规则保持；主站页面仍不实时串联三副本。
- 私有缓存与日志：API no-store、PWA 私有缓存拒绝规则保持；日志按敏感键与模式脱敏仍只是兜底，调用方不得传完整请求或个人正文。
