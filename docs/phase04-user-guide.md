# 阶段 04 使用说明：自由导航、活动与 PWA

本文件面向**使用者**（也是自用维护者的操作手册），说明阶段 04 实际可用的功能、每一步的真实行为、
以及明确**不承诺**的部分。命令与接口的完整列表见 [`README.md`](../README.md)；
设计取舍见 [`docs/adr/0004-phase04-navigation.md`](adr/0004-phase04-navigation.md)。

> 本阶段**未部署**：以下操作都在本地开发环境（`wrangler dev` + 本地 D1）验证。
> 没有任何远程 Cloudflare 资源被创建。

---

## 1. 先决条件

1. 本地服务：`pnpm install --frozen-lockfile` → `pnpm db:migrate:local` → `pnpm dev:api`（Worker + 静态资源同域）。
2. 一次性初始化工作空间（只在**第一次**需要）：

   ```bash
   # 生成一次性初始化密钥（本地随机值，不要复用生产密钥）
   node -e "console.log('local-'+require('crypto').randomBytes(32).toString('hex'))"
   # 写入 .dev.vars 的 BOOTSTRAP_SECRET，然后重启 wrangler dev
   curl -X POST http://127.0.0.1:8787/api/v1/identity/bootstrap \
     -H "Content-Type: application/json" -H "X-Bootstrap-Secret: <上面的密钥>" \
     -d '{"deviceName":"我的桌面浏览器"}'
   ```

   把返回的 `deviceToken` 存进页面里的「会话凭证」入口（阶段 02 已有）。
   **Token 只在内存里**，刷新页面需要重新输入；不要把它写进任何文件或 URL。
3. 启用真实业务模块（模块未启用时组件不会执行，只会显示降级卡片）：
   在「模块管理」里启用 **`ff14.navigation`（导航）** 与 **`ff14.events`（活动）**。

---

## 2. 导航：推荐目录与个人副本是**两件事**

- 系统目录（`GET /api/v1/navigation/catalog`）是**只读**的：里面每一条都有
  `sourceUrl`（据以核对的官方/作者页面）、`verifiedAt`（核对时间）、`region`（国服/国际服/通用）
  与 `verificationStatus`。阶段 04 只收录**少量已核对来源**的条目，不编造网站，
  也**不声称**网站当前在线（没有任何探测，健康状态一律显示「未探测」）。
- 「导入」产生的是**你自己的副本**：可以改名、改 URL、改描述、改标签、换图标、
  改打开方式、改区服、加收藏、换分组、调顺序、删除。
- **目录升级不会覆盖你的修改**：只要你对某条副本改过任何内容，它就标记为
  `user_modified`，目录升级时**跳过**（除非你在界面上明确勾选「覆盖我的修改」）。
- **目录升级不会复活你删掉的东西**：删除是墓碑（`deleted_at`）。被删除的条目在目录升级时
  永远是 `tombstoned` → **跳过**。只有你对同一条目点「显式再次导入」时才会恢复它
  （这是唯一的复活入口，并且界面上会明确提示「这会恢复你删除过的条目」）。
- 「目录版本升级」和「再次导入」是两件事：前者只更新系统目录表，后者才可能写你的副本。

### 2.1 分组（分类）与多分组

- 「分类」与「分组」在数据里是同一个东西（`workspace_nav_groups`）：推荐目录条目自带的
  `category` 只在**导入时**用于创建/关联一个同名分组，之后完全由你控制。
- 一个链接可以同时属于多个分组；组内顺序与整体顺序都能单独调整。
- 删除分组**不删除链接**（链接只是失去了这个归属）。

### 2.2 搜索、筛选与排序

- 搜索匹配**标题、别名、描述、标签**（大小写与全角/半角不敏感）。
- 可按分组、区服、标签、收藏筛选；排序有「个人顺序 / 标题 / 最近修改 / 收藏优先」。
- 这些规则在服务端与前端是**同一份实现**（`packages/shared/src/nav-api.ts` 的纯函数），
  因此「服务端筛出来的」和「Widget 里看到的」不会不一致。

### 2.3 从浏览器书签导入

1. 在导航视图打开「导入」面板，选择或粘贴浏览器导出的书签 HTML（或结构化 JSON）。
2. **先在本地预览**：逐项显示 `items`（会被导入）与 `skipped`（会被跳过的，附原因：
   非 https、重复、缺标题、超限…）。跳过项不会静默消失。
3. 只有你确认后才提交；服务端会**重新校验**每一项，并按 `operationId` 幂等写入。
4. 解析是严格的数据解析：只把 `<a href>` 与 `<h3>` 当数据读，`<script>`/`<style>` 内容整体丢弃，
   外来 HTML **不会**被插入页面，也**不会**被执行。
5. 导出的 JSON（`GET /api/v1/me/navigation/export`）能被读回（roundtrip），且**不含任何凭证**。

### 2.4 说不的地方（诚实边界）

- 只允许 `https:`。`http:` 会被拒绝（本阶段**不授予**任何 http 例外）；
  `javascript:`/`data:`/`file:`/`blob:` 等一律拒绝。
- 健康状态不在本阶段探测：403 永远不会被说成「永久失效」（只有 `maybe_blocked` 这个可能值），
  而且没有任何代码把导航 URL 交给服务端去请求（因此也不存在内网探测面）。

## 3. 把导航放到你的页面上（Widget）

- 启用 `ff14.navigation` 后，组件库里会出现两个 Widget：
  - **常用网站（`nav-quick-links`）**：按收藏/分组显示，可配置标题、分组、只看收藏、条数。
  - **导航搜索与分类（`nav-search`）**：带搜索框与区服/标签/排序筛选。
- 它们都放在阶段 03 的可定制工作台上，随页面/断点布局一起保存；
  移除 Widget **不删除**任何导航数据（移除 ≠ 删数据）。
- 停用 `ff14.navigation` 模块时，其 Widget 会显示降级卡片并**停止执行**，
  导航数据与你的页面布局都保留；重新启用后立刻可用。
- Widget 拿不到设备 Token、也拿不到任意 URL：它只能通过「模块数据端口」调用本模块声明过的操作
  （端口每次调用前会复检模块门禁，所以停用/卸载/切换中的模块不会被绕过）。

## 4. 活动（人工维护）

- 启用 `ff14.events` 后，页面可放 **即将开始/进行中（`events-upcoming`）** 与
  **活动维护（`events-manage`）** 两个 Widget。
- 活动由你**手工录入**：标题、区服（国服 / 国际服）、开始与结束时间、描述、来源链接（可选）。
  时间按本地时间输入、以 UTC 毫秒保存，因此换时区看不会漂移。
- 过期逻辑是纯函数（未开始 / 进行中 / 已结束），列表与徽章都按它显示。
- **个人活动的验证状态恒为「未验证」**：这是你自己记的来源，服务端不会把它升级成「已核实」。
  界面原样标注，不声称准确提醒。
- 公共来源活动（`GET /api/v1/events`）与个人活动**分表**：个人活动永远不会出现在公共响应里。
  阶段 04 的公共表是**空表**——不捆绑任何未经核实的数据，界面显示「没有可验证的公共来源活动」。
- 本阶段**不做**：抓取器、鱼类计算、提醒调度、Cron 与通知（属于阶段 05）。

## 5. 多设备：同步、冲突与草稿

- 新增的**只读**水位端点 `GET /api/v1/me/sync/changes?since=<游标>&limit=N` 返回本工作空间
  自某个游标以来的变更（页面/实例/布局/导航链接/分组/成员关系/模块/个人活动），
  删除以 `op:"delete"` 墓碑形式传播。
- 客户端规则（阶段 04 实现）：
  - **快照权威、增量通知**：导航视图在工作台/导航视图挂载、窗口重新获得焦点、以及定时
    轮询时应用增量；显式刷新时以完整快照对齐。
  - **墓碑应用后不复活**：收到某个链接/分组的 `delete` 后本地移除；后续任何合并都不会把它加回来。
  - **草稿保留**：正在编辑且未保存时，如果该条目在其它设备上被改动或删除，
    界面会**保留你的草稿并提示冲突**，由你决定放弃或重新载入；后台刷新**不会**静默覆盖。
  - **保存仍走 revision CAS**：保存时带 `expectedRevision`，服务端发现陈旧写会返回**结构化 409**
    （告诉你服务器上是第几版、你基于第几版），不会盲目覆盖。
- 布局同理：桌面/平板/手机是**独立修订号**，手机端保存不会覆盖桌面坐标（阶段 03 已实现）。
- 诚实说明：阶段 04 **不做墓碑 GC**（避免"提前删掉仍要同步的墓碑"），
  水位是毫秒粒度——与「快照对齐」配合使用，因此不会永久丢失，最坏情况是晚一个刷新周期看到。

## 6. PWA：安装、离线与更新

- 浏览器地址栏会出现「安装」入口（`manifest.webmanifest` + 192/512 图标，含 maskable）。
- **离线只显示公开内容**：Service Worker 只缓存公开静态资源与公开目录
  （`/api/v1/health`、`/api/v1/modules/catalog`、`/api/v1/navigation/catalog`、`/api/v1/events`）。
  `/api/v1/me/*`、任何带 `Authorization` 的请求与响应、备份、个人活动与个人导航**都不进缓存**。
- 离线时界面明确提示：「离线：显示的是缓存的公开内容；私有修改不会在离线时持久化到服务端」——
  这是事实陈述，不是免责声明：离线时**不会**假装你的修改已保存。
- 更新：Service Worker 自己**不会**直接激活新版本。页面在有未保存草稿时会**拒绝**更新并提示你，
  避免无提示重载丢掉正在编辑的内容。
- 退出或切换凭证时，私有相关缓存会被清理，旧工作空间的数据不会继续从缓存可见。

---

## 7. 备份与导出

- 导航：`GET /api/v1/me/navigation/export` 导出个人导航（版本化 JSON、可读回、不含凭证）。
- 工作台：阶段 03 的备份/导入/撤销继续可用（见 README 第 6 节）。
- 两者都**不含**任何设备 Token、恢复密钥或服务端秘密。

---

## 8. 本阶段明确不做的事（不要读成已完成）

- 不部署、不创建远程 D1/Worker、不绑定域名、不注册 Cron。
- 不做服务端 URL 探测与健康检查；不做抓取器；不做鱼类计算；不做提醒/推送。
- 不做墓碑 GC；不做 WebDAV/鱼糕同步（阶段 06）。
- 前端身份界面仍只有「会话内存凭证」最小入口（初始化向导/配对/设备管理 UI 未实现）。
