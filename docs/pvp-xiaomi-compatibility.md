# PVP 0.3：小米背景兼容与紧凑布局

## 反馈与修正

用户在小米 17 Pro Max、澎湃 OS 4 上反馈：调整至某些尺寸时背景透明，深色文字融入壁纸。截图能证实显示异常，但无法仅靠截图确定宿主内部的唯一原因。

0.3 移除通过 RemoteViews 先清空再设置根背景的代码，也移除代码中硬编码的配色动作。所有现用布局采用静态 XML 不透明 shape：FrameLayout 根底色之外，另有铺满整个卡片的 ImageView 底层；触摸 ripple 放在独立 foreground，不承担填充背景。即使宿主清掉根背景，底层仍可绘制不透明表面。

小米、Redmi、POCO 设备优先按传统 min/max 宽高 Bundle 和 `onAppWidgetOptionsChanged` 选布局，即使宿主同时上报新版尺寸列表也不使用响应式映射。其他设备继续支持尺寸映射。小于声明最小尺寸时使用两行紧凑回退，不让背景变成透明。

小米官方说明宿主可能通过缓存 RemoteViews 重建夜间视图，因此配色仅由 XML 的 values/values-night 决定，避免旧 RemoteViews 中的颜色动作覆盖夜间主题：[官方 Q&A](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1591)。

## 尺寸与排版

去除所有卡片上的“国服／内置规则／已同步”等状态行，保留数据语义和后台缓存判断。地图主字为 14–16sp，标签为 10sp，内边距 6–10dp，圆角 16dp，减少重复标题与纵向间隔。

参考预览尺寸：小 140×100dp、中 280×140dp、大 280×260dp；分别较 0.2 的 155×155、320×180、320×340dp 收紧。小号初始格子申请为 2×1，最小缩放为 120×88dp；实际栅格大小由桌面决定。

自动密度：低于 120×88dp 采用极小回退；宽 ≥220dp 且高 ≥120dp 使用中密度双栏；窄高 ≥120×220dp 使用中密度上下布局；≥260×240dp 使用大密度排期表。极小空间允许省略显示文字，完整名称仍在读屏描述中，不能承诺任意小尺寸都容纳全部信息。

## 负一屏

当前是原生 Android AppWidget 调试包。系统若开放对应入口，可尝试负一屏右上角“+”、小部件中心的安卓小部件入口，或系统允许的桌面组件拖动；不同系统不保证原生组件可放入负一屏。

小米专属组件中心及负一屏卡片属于额外接入体系，涉及独立进程、曝光刷新、应用发布与小部件审核。当前包没有完成小米平台上架，未设置虚假的“已支持负一屏”标识，也不把 Android 的 home_screen/keyguard 属性误当作负一屏能力。

应用内增加“负一屏添加说明”，提供条件说明和官方入口。未来如提供开发者账号、正式签名包及平台准入，可单独实施小米组件接入，并在实体机验收后宣称支持。

## 验证

- Android 30 项测试、lintDebug、assembleDebug 通过。
- Native Graphics 在 96×64 至 280×260dp 范围，主动移除根背景后检查中心像素 alpha=255，验证独立背景层。
- 缓存的日间 RemoteViews 在夜间 Context 重建后，文字取值为夜间 XML 配色。
- 模拟 Xiaomi manufacturer，确认同时收到尺寸列表和传统宽高时使用传统路径。
- 100/115/130/200% 字体下检查新的最小尺寸及小中大边界；API 30/35 同实例反复切换尺寸。
- Android 15 模拟器覆盖安装、原生预览检查浅色/深色/大字体；APK 沿用同一个 Debug 签名。小米 17 Pro Max / 澎湃 OS 4 仍待用户覆盖安装实测。
