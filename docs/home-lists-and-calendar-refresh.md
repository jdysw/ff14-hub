# 首页列表与官方活动同步

活动列表保留全部有效日程，桌面同时可见 4 项（每行 96px），手机最多 4 项（每行 124px）；其余独立滚动。鱼窗默认未来 24 小时，全部匹配条目进入最多四行的滚动窗口。模块的标题、统计与操作区不滚动。活动底部的其余日程/待核实公告按钮已移除，完整日历入口继续保留。

导航分类全部展开，手机换行，不隐藏在更多分类或下拉选择中。

## 官方活动：有访问时近实时更新

- 固定官方源：`https://cqnews.web.sdo.com/api/news/newsList` 和 `newsDetail`，以及校验过的盛趣活动专题。不是第三方活动源。
- 新闻 API 返回公告，不保证结构化活动日期。只有正文或专题中明确的起止时间才进入倒计时；发布时间不代替活动时间。
- 原先有 D1 快照就不再请求上游的问题已修正。快照超过 5 分钟后，公共 JSON/ICS 请求通过 `ctx.waitUntil()` 在后台尝试刷新，不阻塞现有快照响应。
- 全边缘共用现有 D1 原子限流器，专用 `public-calendar:official-refresh:cn` 配额每 5 分钟最多一次；不新增数据库迁移或 Cron。
- 上游请求整体 20 秒预算、单请求 10 秒，响应最多 1MB。没有跨请求复用 I/O Promise。
- 只接受完整、非空、来源正确的新数据，条件 UPSERT 防止较慢结果覆盖更新的快照。失败不删除数据、不修改旧同步时间；人工编辑层仍独立保留。
- 前台页面每 60 秒获取一次应用接口，后台标签暂停轮询，返回前台时刷新。刷新失败保留上一份列表并标记缓存状态。
- 这是受限频率的近实时刷新，不是官方推送。Cloudflare 到盛趣的网络异常时会继续使用最近快照；本机官方接口可达不等于云端出站一定可达。

## 验证

官方 API 本机实测成功：30 条公告，其中 4 项仍有有效日程；未将本机采集结果直接写入生产库。
ego lite 实测 3440px 活动列表 384px、行高 96px；鱼窗列表 256px、行高 64px，包含 284 条匹配结果。滚轮操作后列表 scrollTop 为 400，页面 scrollY、标题和统计位置均不变。2560、1440、768、390、320px 全分类可见，无页面或分类横向溢出。
单元测试覆盖轮询失败保留内容、24 小时时间范围、并发刷新配额、上游失败保留快照、空/部分/私有内容拒绝及旧响应不覆盖。

## Worker 请求兼容性

Cloudflare 的生产运行时不支持 Fetch 的 `redirect: 'error'`，会在发送请求之前抛出 TypeError；本机 Node 和被模拟的测试 fetch 没有暴露这一差异。官方 JSON 和专题 HTML 请求现在统一使用 `manual`，并通过 `response.ok` 拒绝 3xx，因此仍不跟随官方跳转或跨域跳转。失败诊断仅包含固定端点类型、HTTP 状态和脱敏的原生错误类型，不记录公告正文、URL 查询、凭证或个人数据。
