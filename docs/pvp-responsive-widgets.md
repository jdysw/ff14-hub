# PVP 合并组件与动态尺寸（0.2）

## 轮换更正

国服纷争前线每日北京时间 **23:00** 换图。按用户校准，2026-10-20 23:00 至 10-21 23:00 为第二次尘封秘岩，10-21 23:00 切换周边遗迹群。共享锚点为 `2026-10-20T15:00:00Z`，版本 `2026-10-21-cn-v2`。水晶冲突每小时整点换图，原锚点和顺序保持不变。

Web、公开 API 和生成的 Android 离线资产共用 TypeScript 规则。API schemaVersion 仍为 1，旧客户端联网后可以读取修正后的锚点；新版 Android 拒绝已知错误的 v1 规则缓存，离线时使用新版内置规则。

## 同一组件动态改变内容

小、中、大是系统组件列表的初始尺寸入口，**不是锁定的三种信息模式**。三个入口都显示合并的前线与水晶冲突，并能从最小尺寸拖动到较大尺寸，内容根据实际可用 dp 决定。

| 空间 | 布局 | 信息 |
|---|---|---|
| 小 / 窄，参考 155×155dp | 两组纵向对齐 | 两种当前地图、规则来源 |
| 宽 ≥240dp、高 ≥180dp | 两个并排战场 | 当前、下一张、独立系统倒计时和换图时间 |
| 窄而高：宽 ≥140dp、高 ≥320dp | 两种战场上下排列 | 与中尺寸相同的信息，适配 2×4 等竖长空间 |
| 宽 ≥280dp、高 ≥320dp | 双栏加后续轮换表 | 中尺寸全部信息，另加每种模式未来三轮 |

大字体优先保留可读性：系统字体超过默认的 110% 时降低一级信息密度。窄尺寸仅保留两种战场和完整地图名；大尺寸保留当前、下一张与倒计时，省略排期表。

- Android 12+：桌面提供 `OPTION_APPWIDGET_SIZES` 时使用 `RemoteViews(Map<SizeF, RemoteViews>)`；桌面可在缩放时选择布局，无需持续轮询。
- 旧 Android，以及只报告传统尺寸 Bundle 的 MIUI/HyperOS 桌面：通过 `onAppWidgetOptionsChanged` 重新计算密度，兼容横竖屏的 min/max 尺寸。
- 使用 `resizeMode=horizontal|vertical` 和最小缩放范围；没有要求小米专属接口或第三方桌面。实际栅格、最小尺寸和是否显示拖动手柄仍由桌面决定，未经小米实体机验收不能承诺所有型号行为一致。
- 保留原 `FrontlineWidgetProvider`、`CrystallineWidgetProvider` 的组件身份，现有桌面实例在升级后切换成合并视图，不丢失已放置实例。新增大号入口。
- 合并组件始终调度两种模式的最早边界；23:00 前线与水晶一起换图时只有一个闹钟。非精确闹钟仍受系统省电限制。

## 视觉规范

采用干净的战场速览卡片，不使用地图大图或多层装饰。地图名是视觉主角，去掉括号中的玩法后缀；前线以冷蓝、水晶以棕金区分，文字标签同时保留，不单靠颜色传达含义。

语义颜色：浅色表面 `#F7F9FC`、正文 `#172B42`、辅助文字 `#526477`、前线 `#365F86`、水晶 `#835C2D`；深色分别为 `#182431`、`#F0F4F8`、`#B8C6D5`、`#A7C9EB`、`#EAC68F`。系统 sans-serif 字体，地图 16–19sp，辅助时间 11–14sp；22dp 圆角、轻边界、整卡触摸反馈。当前与下轮信息形成固定对齐，而非按屏幕大小等比放大。

应用内“预览三种尺寸”使用实际 RemoteViews 和当前规则，不是另一套示意 UI。读屏描述包含两种完整地图名、下一张和换图时间。

参考：[Android 官方响应式组件布局](https://developer.android.com/develop/ui/views/appwidgets/layouts)。

## 验收重点

- TypeScript/Kotlin 验证 22:59:59.999、23:00:00.000、午夜，以及时区变化；午夜不应再额外换图。
- 错误零点规则缓存不得继续使用。
- 同一个 ID 在小→中→大→小切换时增减真实信息；传统尺寸 Bundle 在 API 30、35 均覆盖。
- Native Graphics 下检查正常及大字体的文字边界、深色语义颜色；模拟器直接查看实际布局并检查桌面缩放。小米实体机验收单独记录。
