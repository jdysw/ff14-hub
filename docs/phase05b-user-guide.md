# 提醒管理框架（05B）

在“模块管理”启用“提醒管理”，然后进入系统栏的同名页面，或向工作台添加“提醒规则与投递记录”组件。
先建立个人活动，或导入鱼类目录，再创建提醒规则，选择区服、目标和提前分钟。规则支持编辑、停用与删除。
鱼类还需启用钓鱼模块、设置提醒偏好；示例/未验证/复杂条件规则不会生成真实通知任务。

本轮仍是框架交付，通知使用通用占位文案。具体模板、全量数据、真实设备收件和生产定时运行后续单独验证。
“检查到期任务”会有界生成/处理当前工作空间任务。同一规则和事件不会重复建逻辑任务。
修改规则会取消旧版本任务。失败保存保留表单输入，冲突时请刷新并重新编辑。

## 渠道配置与状态

默认没有VAPID配置，也没有注册远程Cron。界面会显示“推送渠道未配置”，到期任务处于“渠道未就绪”，
不会伪造成功投递，也不会因为没有配置就耗尽重试次数。

后续部署时在服务端配置`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`（mailto或HTTPS联系地址）。
私钥不要提交到仓库；代码不会自动生成或写入密钥。配置就绪后，用户需主动点击“订阅当前设备”并批准浏览器权限。
只支持Google FCM、Mozilla、Apple的HTTPS推送端点。停用当前设备接收只影响本设备。

“推送服务已接受”只说明服务端接受了请求，不是设备收件回执。临时失败会重试，404/410会停用失效端点。
模块停用、规则删除/更新、活动过期、设备撤销、鱼类已完成都会在发送前重新检查。
由于网络结果可能不明确，物理推送按至少一次处理，不能保证绝不重复；稳定tag尽量减少重复展示。

界面展示最近100条任务/投递记录。摘要与免打扰（HUB-027，P1）尚未实现。

## 本地验收

`pnpm run e2e:phase05b`复用现有隔离D1/Worker/Chromium编排，使用随机一次性凭证和人工活动，
验证规则增改删、任务去重、未配置渠道、工作台组件与窄屏表单。不会发送真实外部通知。
`worker/test/reminders.spec.ts`验证租约并发/过期接管、旧执行者隔离、设备与模块抑制、按设备重试、
失效端点及真实WebCrypto加密（仅HTTP使用替身）。没有生产资源变更。
