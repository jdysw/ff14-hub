# 本机 WebDAV 档案与同步框架（06B）

在「数据同步」页下方新增**本机 WebDAV 档案**面板。它只做一件事：把 WebDAV 配置
中的用户名、口令用 WebCrypto AES-GCM 加密后保存在**本机浏览器**里。
名称、DAV 地址与作用域标识作为本机档案元数据可读；它们不会上传到 Hub。

- 加密密钥不可导出（`extractable:false`），以结构化克隆存进 IndexedDB；
- 本阶段**不会发起任何 WebDAV 网络请求**，也不会把 DAV 地址/账号/口令发送给 Hub；
- Hub 设备令牌只存在于会话内存，不写入本机保险箱，也不会显示在页面上；
- 保存成功后口令输入框立即清空；列表只显示名称、区服与 DAV 地址；
  「校验可解密」只报告「可解密（仅校验，未显示口令）」；删除需要显式勾选确认。

密钥与记录都绑定作用域：换工作空间、换区服、换站点源、换 DAV 地址、换用途，或记录被改动，
都会解密失败并报错（不会静默当成「没有记录」）。切换会话后，面板只会显示**当前**工作空间
在当前站点源与区服下的档案；上一个会话的列表与校验结果不会带过来。

## 本轮真正实现了什么

`packages/fish-sync` 新增/完成三块**可单测**的零件：

1. `vault.ts`：本机保险箱（不可导出 AES-GCM 密钥 + IndexedDB、AAD 作用域绑定、凭证/检查点/归档记录）。
2. `coordinator.ts`：纯注入端口的三方协调器。顺序固定为 **WebDAV → Hub → 本地**；
   计划在**任何副作用之前**先落盘；每个阶段后更新检查点；最后重读三方校验一致才报成功。
   恢复必须重读重校验：出现计划之外的新变化就停下并保留待处理意图；
   Hub 响应丢失时用同一 `{token, operationId}` 幂等重放取得操作回执，并校验完整字段读集；
   相同值不能单独证明提交归属；本地 CAS 须同时保存操作回执，DAV 须匹配事务 ID 与 ETag。
   基线分别保存各副本的字段修订，预览不会自动恢复 DAV 写入。
   只有显式给出被检查过的 `operationId` 才能归档/丢弃待处理意图。
   Hub 只接收最小字段意图（每次最多 200 项，超限整批拒绝）；扩展字段永不上传。
3. `userscript.ts`：受限油猴适配器骨架。**当前不可发布**——鱼糕站点存储 API 尚未审计，
   域名白名单为空，因此适配器是 disabled 的；任何读写都会抛策略错误，不会用猜测的键名实现。

## 这一轮**没有**做到什么（请按此理解，不要过度解读）

- 没有真实鱼糕站点的存储适配，也没有可发布的油猴脚本（源码未审计 → 不猜键名）。
- 没有真实 WebDAV 服务端联调：协议单测用的是内存假服务器。
- 网页端**没有**把三份副本自动串起来：协调器已实现且有单测，但尚未接入页面；
  页面上的写入仍然只走 06A 的显式导入预览。
- 跨标签页互斥尚未接入（当前锁只在同一 JS 上下文内生效）。
- 没有新增鱼类数据集或模板内容，没有部署、没有创建任何远程资源。

## 验收入口

- `pnpm --filter @ff14-hub/fish-sync test`：
  - `vault.spec.ts`：密文不含明文、AAD 作用域与篡改一律拒绝、并发首次初始化只写一个密钥、
    存储错误与解密错误区分、安全 URL 校验、列表按作用域过滤、删除清空三类记录。
  - `coordinator.spec.ts`：三方合并与最小 Hub 意图、冲突阻塞全部写入、首次同步的缺位语义、
    DAV 中断恢复、Hub 响应丢失（已提交/未提交两条路径）、最后一个检查点丢失后的恢复、
    过期/陈旧预览、超 200 项整批拒绝、恢复期间他方改动硬阻塞、检查点损坏/不可读时拒绝启动、
    按档案独占锁、归档/丢弃的 operationId 校验。
  - `userscript.spec.ts`：通配符/HTTP/回环/未审计域名、远程注入与网络 API、内嵌凭证、
    当前审计状态下不可发布、已审计配置下的 CAS 委派且不触网。
- `apps/web/test/client-vault.spec.tsx`：面板只按受信工作空间作用域落盘、保存后清空口令、
  页面与文档不出现口令、校验不显示口令、删除需确认、隐藏视图保留草稿、跨会话不发布旧档案、
  非法 DAV 地址不写入。
- `pnpm run e2e:phase06b`：真实浏览器 + 真实 IndexedDB。保存 → **真实刷新页面** → 列表仍在、
  可解密；直接读 IndexedDB 证明主密钥 `extractable:false`、算法为 AES-GCM、
  `crypto.subtle.exportKey` 被拒绝；存储密文中不含口令/用户名/设备令牌；全程没有任何
  DAV 请求（所有出站请求都留在本站源）；删除后记录数归零；窄屏无横向溢出。

全部使用本地模拟资源（本地 `wrangler dev` + 本地 D1 + 内存 DAV/Hub 假端口）。
没有部署、没有连接用户真实 WebDAV、没有修改鱼糕站点数据。Sonar-only 问题仍按要求延期。
