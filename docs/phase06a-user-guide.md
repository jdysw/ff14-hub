# 数据同步框架（06A）

在模块管理中启用“钓鱼手账”和“数据同步”。进入“数据同步”，或在工作台添加“鱼糕导入与同步”组件。
选择正确区服，上传/粘贴含`completed`、`pinned`、`alarmFish`三个数组的鱼糕JSON，点击“预览导入”。
这是一份文件到Hub的**显式导入预览**，不是已运行的自动三方同步。

核对每项已钓获/收藏/提醒偏好的“是/否”，先下载变更前备份，再勾选确认后应用。取消已钓到、取消收藏、
取消提醒均会真实写入false，不会用并集把它加回来。每次最多200项字段变化，超限整批拒绝；不会偷偷只导一部分。
重复提交同一操作不会重复改动。网络/并发冲突保留输入，请重新预览。

未知鱼类ID会保留，并在未来导入目录后自动归位。扩展字段只保留在当前客户端/导出文件中，不上传Hub；
导出会将最新服务器三集合与当前选中文件的扩展字段组合。另一客户端仅能取得服务器最小进度数据，
不会从服务器获取本机扩展字段。关闭页面前请导出需要保留的本地扩展数据。

“预览撤销”展示审计记录的反向变化，也要先备份、确认。如果之后有新字段编辑，撤销会拒绝覆盖。
页面显示的是最后一次Hub导入时间，不代表WebDAV当前状态。

## 客户端SDK边界

`packages/fish-sync`包含JSON适配、三方合并冲突列表和独立WebDAV客户端。WebDAV要求HTTPS、独立于Hub的源、
强ETag和正确条件写；双文件准备/提交记录支持中断恢复。凭证只在调用客户端的内存中保管。
目前主站没有收集WebDAV凭证的表单，服务端没有代理WebDAV的路径，也没有发布带通配`@connect`的油猴脚本。

真实鱼糕站点存储适配、受限域名userscript打包、凭证加密保管、跨三份副本的检查点编排及实际WebDAV联调
将在06B接入。不要把本轮协议单测通过解读成真实站点已可自动同步。具体模板内容继续后补。

## 验收入口

- `pnpm --filter @ff14-hub/fish-sync test`：未知字段、相反意图、ETag、两阶段中断及并发保护。
- `worker/test/fish-sync.spec.ts`：真实D1的隔离/200字段事务/幂等/回滚/故障回滚/未知ID归位。
- `pnpm run e2e:phase06a`：真实浏览器的文件预览、备份、跨客户端读取、撤销、扩展字段不进后端和窄屏。

全部使用本地模拟资源。没有部署、没有连接用户真实WebDAV、没有修改鱼糕站点数据。Sonar-only问题仍按用户要求延期。
